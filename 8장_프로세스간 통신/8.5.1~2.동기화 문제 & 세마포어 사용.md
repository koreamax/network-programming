# 8.5 세마포어 (Semaphore) — 8.5.1~2 동기화 문제 & 세마포어 사용

## 1. 동기화 문제와 크리티컬 영역

- **크리티컬 영역(critical region)**: 동기화 문제가 발생할 수 있는 코드 블록
- 둘 이상의 프로세스가 같은 공유 데이터에 동시에 접근하면 값이 부정확해질 수 있다.

### 예시 (x의 초기값 = 3)
```c
// 프로세스 A
{ printf("A: before increase x = %d\n", x);
  x++;
  printf("A: after increase x = %d\n", x); }

// 프로세스 B
{ printf("B: before decrease x = %d\n", x);
  x--;
  printf("B: after decrease x = %d\n", x); }
```

#### 경우 1 — A와 B가 차례로 수행 (정상)
```
A: before x = 3,  A: after x = 4   // A는 x=4 사용
B: before x = 4,  B: after x = 3   // B는 x=3 사용
```

#### 경우 2 — A가 `x++` 직전에 B가 스케줄됨
```
A: before x = 3,  B: before x = 3   // B 스케줄 시점에 x는 아직 3
B: after x = 2,   A: after x = 3
```
→ 끼어듦으로 인해 최종 결과가 어긋남.

#### 경우 3 — A가 `x++` 직후에 B가 스케줄됨
```
A: before x = 3,  B: before x = 4   // x++ 직후라 4
B: after x = 3,   A: after x = 3
```

> 실행 순서(스케줄링)에 따라 결과가 달라지는 것이 동기화 문제의 핵심이다.

## 2. 세마포어 정의

> **세마포어** = "어떤 공유 데이터에 대해 현재 사용 가능한 데이터의 수"

### 동작 원리 (앞 예의 공유 데이터 x, 세마포어 S)
프로세스가 크리티컬 영역에 들어가기 전에 먼저 세마포어 `S` 값을 확인한다.

| `S` 값 | 의미 / 동작 |
|--------|-------------|
| `S == 0` | 사용 여유 없음 (다른 프로세스가 x 사용 중) → `S == 1`이 될 때까지 **대기** |
| `S == 1` | x를 바로 접근 가능 → **`S = 0`으로 만든 후** x 접근 |

- 크리티컬 영역에서 나오면 `S` 값을 **1 증가**시킨다.

### 이진 vs 카운트 세마포어
| 종류 | 설명 |
|------|------|
| **이진(binary) 세마포어** | `S`가 **0과 1** 값만 가짐 |
| **카운트(count) 세마포어** | 공유 가능한 데이터가 둘 이상일 때 사용. 데이터가 5개면 최대 5까지 가능 |

## 3. `semget()` — 세마포어 생성

```c
int semget(key_t key, int nsems, int semflg);
```

| 인자 | 설명 |
|------|------|
| `key` | 세마포어를 구분하는 키. 다른 프로세스가 사용하려면 이 키 값을 알아야 함 |
| `nsems` | **세마포어 집합**을 구성하는 멤버의 수 (세마포어 배열의 크기) |
| `semflg` | 생성 옵션 / 접근 권한 (비트마스크) |

### key 관련
- `IPC_PRIVATE` 사용 시: 키 없는 세마포어 객체 생성, 다른 프로세스 접근 불가
- 세마포어 생성 후 `fork()`하면 자식은 세마포어 ID를 **상속** → `semget()` 없이 접근 가능
- 따라서 `IPC_PRIVATE` key는 **부모-자식 프로세스간 통신**에 편리

### semflg
```c
mode = 0660;
semget(key, nsems, IPC_CREAT | mode);
// key에 해당하는 객체가 이미 존재하면 기존 세마포어 ID 반환, 없으면 새로 생성 후 ID 반환

semget(key, nsems, IPC_CREAT | IPC_EXCL | mode);
// 객체가 이미 존재하면 에러(-1) 반환
```

> **세마포어 집합**: 세마포어가 여러 개 모인 집합, 일종의 세마포어 배열.

## 4. `semop()` — 세마포어 연산

세마포어 값을 증가/감소시키는 것을 **세마포어 연산**이라 한다.

```c
int semop(int semid, struct sembuf *operations, unsigned nsops);
```

| 인자 | 설명 |
|------|------|
| `semid` | 세마포어 ID |
| `operations` | 연산 내용을 담은 `sembuf` 구조체 (배열) |
| `nsops` | `operations`가 가진 리스트(연산) 개수 |

### `struct sembuf`
```c
struct sembuf {
    short sem_num;   // 멤버 세마포어 번호 (첫 멤버가 0번)
    short sem_op;    // 연산 내용 (증가/감소시킬 값)
    short sem_flg;   // 조작 플래그
};
```

- `sem_op` 예: `+1`(1 증가), `-3`(3 감소 = 공유 데이터 3개를 한 번에 사용)
- `sem_flg` 옵션 (비트마스크)
  | 값 | 동작 |
  |----|------|
  | `0` | 기본값. **블로킹 모드** — 필요한 공유 데이터가 준비될 때까지 블록 |
  | `IPC_NOWAIT` | 세마포어 값이 부족해도 블록되지 않고 리턴 |
  | `SEM_UNDO` | 프로세스 종료 시 커널이 해당 세마포어 연산을 **취소(되돌림)** |

## 5. 사용 예 — 연필 3자루 + 노트 3권

공유 데이터: 연필 3자루, 노트 3권.
각 프로세스는 한 번에 연필 1자루 + 노트 1권을 동시에 사용하며, 이런 프로세스가 10개 실행 중.

- 한 프로세스가 `semget()`으로 세마포어 객체 생성, 나머지는 ID로 접근

```c
// 연필용 1개 + 노트용 1개 → 멤버가 2인 세마포어 집합
semid = semget(mykey, 2, IPC_CREAT | mode);
// 멤버 0 = 연필, 멤버 1 = 노트 (초기값 설정)

// 연산용 sembuf 정의
struct sembuf increase[] = { {0, +1, SEM_UNDO}, {1, +1, SEM_UNDO} };
struct sembuf decrease[] = { {0, -1, SEM_UNDO}, {1, -1, SEM_UNDO} };

// 사용 전: 세마포어 감소 (자원 확보)
semop(semid, &decrease[0], 1);   // 연필
semop(semid, &decrease[1], 1);   // 노트

// --- 연필과 노트 사용 ---

// 사용 후: 세마포어 증가 (자원 반납)
semop(semid, &increase[0], 1);   // 연필
semop(semid, &increase[1], 1);   // 노트
```

---

## 정리

- 크리티컬 영역에 동시 접근하면 스케줄링 순서에 따라 결과가 달라지는 **동기화 문제** 발생
- 세마포어 = **사용 가능한 공유 데이터의 수**. 진입 전 감소, 진출 후 증가
- 이진 세마포어(0/1) vs 카운트 세마포어(자원 수만큼)
- `semget(key, nsems, semflg)`로 생성 — `nsems`는 세마포어 집합(배열) 크기, `fork` 시 자식이 ID 상속
- `semop(semid, operations, nsops)`로 연산 — `sembuf`의 `sem_op`로 증감, `sem_flg`로 블로킹/`IPC_NOWAIT`/`SEM_UNDO` 제어
- 자원 확보 = 감소, 반납 = 증가 패턴
