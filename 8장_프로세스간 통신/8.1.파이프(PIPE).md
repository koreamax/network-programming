# 8장 프로세스간 통신 (IPC) — 8.1 파이프(PIPE)

## IPC 종류
서버를 멀티 프로세스로 구현할 때 프로세스 사이에 데이터를 주고받는 방법.

- 파이프 (Pipe)
- 메시지 큐 (Message Queue)
- 공유 메모리 (Shared Memory)
- 세마포어 (Semaphore)

---

## 1. 파이프란?

- 운영체제가 제공하는 **프로세스간 통신 채널**
- OS가 관리하는 **임시 파일**이며 프로세스간 데이터 전달용으로 사용
- 송신측이 파이프에 데이터를 **쓰고**, 수신측이 파이프로부터 데이터를 **읽음**
- **스트림(stream) 채널**을 제공

---

## 2. 파이프 생성

```c
#include <unistd.h>
int pipe(int fd[2]);
```

| 디스크립터 | 용도 |
|-----------|------|
| `fd[0]` | 파이프로부터 데이터를 **읽기**(read) |
| `fd[1]` | 파이프에 데이터를 **쓰기**(write) |

> 외우기: **0 = read, 1 = write**

### fork() 직후 상태
`pipe(fd)` 후 `fork()`하면 디스크립터가 복제되어
**부모·자식 모두** `fd[0]`, `fd[1]`을 둘 다 갖게 된다.

```
        부모 프로세스
       fd[1]      fd[0]
       write      read
         |          ↑
         ▼          |
      ═══════ 파이프 ═══════>
         |          ↑
         ▼          |
       fd[1]      fd[0]
       write      read
        자식 프로세스
```

---

## 3. 단방향 채널 — 안 쓰는 끝 닫기

파이프는 **단방향(unidirectional) 스트림**이다.
부모 → 자식 방향으로 전송하려면 안 쓰는 디스크립터를 닫아야 한다.

- 부모: `close(fd[0])` → 읽기 제거, **쓰기만**
- 자식: `close(fd[1])` → 쓰기 제거, **읽기만**

```
부모 프로세스 ──fd[1]──> ═══ 파이프(스트림) ═══> ──fd[0]──> 자식 프로세스
```

### 왜 안 쓰는 끝을 닫는가?
- 데이터 흐름 방향을 명확히 하기 위해
- 특히 **읽는 쪽이 EOF를 정상적으로 감지**하려면
  파이프의 쓰기 디스크립터가 **모두** 닫혀 있어야 하기 때문

---

## 4. 양방향 통신

- 파이프 하나로는 **단방향만** 가능
- 양방향(예: 자식 → 부모 전송)을 위해서는 **파이프를 하나 더 생성**해야 함 (총 2개)

---

## 5. 파이프 생성 & 닫기 코드 흐름

```c
int fd[2];
pid_t pid;

pipe(fd);

if ((pid = fork()) < 0) {        // fork 실패
    exit(0);
}
else if (pid > 0) {              // 부모 프로세스
    close(fd[0]);                // 읽기용 디스크립터 제거 (쓰기만)
}
else if (pid == 0) {             // 자식 프로세스
    close(fd[1]);                // 쓰기용 디스크립터 제거 (읽기만)
}
```

## 6. 파이프를 이용한 UDP 에코 서버/클라이언트

**구성**: 두 개의 프로세스로 구성된 UDP 에코 서버

| 프로세스 | 역할 | 구현 함수 |
|---------|------|----------|
| 부모 | 클라이언트로부터 받은 메시지를 **파이프에 쓰기** | `parent_start()` |
| 자식 | 파이프로부터 데이터를 **읽어서 클라이언트로 에코** | `child_start()` |

### 파이프로 전달하는 데이터 구조
```c
typedef struct mesg {
    struct sockaddr_in addr;   // 클라이언트 주소
    char data[MAX_BUFSZ];      // 에코할 데이터
} mesg_t;
```

### UDP vs TCP — 주소 전달 차이

| | 클라이언트 주소 전달 | 이유 |
|---|:---:|---|
| **UDP** | ✅ 필요 | 비연결형. 매번 누구에게 응답할지(`sendto`) 알아야 함 |
| **TCP** | ❌ 불필요 | 연결형. **소켓을 공유**하므로 상대가 이미 특정됨 |

### 관련 프로그램
- `udpserv_pipeecho.c` : UDP 에코 서버 (부모/자식 + 파이프)
- `udpechocli.c` : UDP 에코 클라이언트
  - UDP 소켓 개설 후 키보드 입력 → `sendto()`로 서버 전송
  - 서버 응답을 `recvfrom()`으로 수신하여 화면 출력

---

## 핵심 요약

1. `fd[0]=read`, `fd[1]=write`
2. 파이프 = OS가 관리하는 임시 파일, **단방향 스트림**
3. `fork()` 후 부모·자식 모두 양쪽 fd 보유 → 안 쓰는 쪽 `close()`
4. EOF 감지 위해 쓰기 디스크립터 전부 닫아야 함
5. 양방향 = 파이프 2개
6. UDP는 주소 전달 필요 / TCP는 소켓 공유로 불필요
