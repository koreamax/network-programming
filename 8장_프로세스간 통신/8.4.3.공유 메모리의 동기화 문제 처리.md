# 8.4 공유 메모리 (Shared Memory) — 8.4.3 공유 메모리의 동기화 문제 처리

## 1. IPC 방식별 특성

| 방식 | 특성 |
|------|------|
| **파이프 / FIFO / 메시지 큐** | 프로세스간 **일대일 통신**에 사용하면 편리 |
| **공유 메모리** | 메모리에 기억해 둔 데이터를 **다수의 프로세스가 복사하여 읽기** 가능 → 같은 데이터를 여러 프로세스에 전달할 때 편리 |

- 공유 메모리는 **여러 프로세스가 동시에 읽기/쓰기**를 하면 **동기화 문제** 발생 가능

---

## 2. 동기화 문제란?

- 하나의 공유 데이터를 **둘 이상의 프로세스가 동시에 접근(읽기 또는 쓰기)** 함으로써 발생하는 문제
- 결과적으로 **데이터 값이 부정확하게 사용**될 수 있음
- 해결 방법 중 하나: **세마포어(semaphore)** 사용

---

## 3. `shmbusyaccess.c` — 동기화 문제 발생 예제

세 개의 프로세스가 경쟁적으로 공유 메모리에 접근하여 동기화 문제를 발생시키는 예.

### 구조
- 공유 메모리를 생성하고 `fork()`를 **두 번** 호출 → 자식 프로세스 2개 생성
- 부모 포함 **총 3개 프로세스**가 공유 메모리를 경쟁적으로 액세스하는 `busy()` 수행
- `busy()`는 공유 메모리 접근 동작으로 `access_shm()`을 호출하며,
  `access_shm()`이 리턴하면 공유 메모리에 한 번 접근한 것으로 간주

### `access_shm()` 동작
1. 호출되면 공유 메모리에 한 번 접근을 시도한 것
2. 공유 메모리에 **자신의 PID를 기록**
3. **지연 시간**을 가짐 (공유 메모리 이용 시간)
4. 공유 메모리에 남아 있는 PID 값과 **자신의 실제 PID를 비교**

| 비교 결과 | 의미 |
|----------|------|
| **다름** | 에러 발생 — `access_shm()`이 리턴하기 전에 **다른 프로세스가 끼어들어 접근**한 것 |
| **같음** | 정상 처리 (정상인 경우 출력 생략) |

> 지연 시간 동안 다른 프로세스가 끼어들어 PID를 덮어쓰면, 기록한 값과 읽은 값이 달라져 동기화 문제가 드러난다.

---

## 4. 근본적인 해결책

- 공유 메모리에 **한 번에 한 프로세스만 접근**하도록 제한
- 이러한 **상호 배제(mutual exclusion)** 제어는 **세마포어**에서 가능

---

## 정리

- 공유 메모리는 여러 프로세스가 동시에 접근하면 **동기화 문제**(데이터 부정확) 발생 가능
- `shmbusyaccess.c`: 3개 프로세스가 PID 기록 → 지연 → 재확인으로 끼어듦을 검출
- 근본 해결책은 **한 번에 한 프로세스만 접근**하도록 제한하는 것 → **세마포어**로 제어
