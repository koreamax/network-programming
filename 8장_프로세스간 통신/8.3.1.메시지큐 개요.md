# 8.3 메시지 큐 (Message Queue) — 8.3.1 개요

## 1. 스트림 기반 vs 메시지 기반

| 구분 | 전송 방식 |
|------|----------|
| **파이프 / FIFO** | **스트림 기반** — 데이터를 연속적으로, **경계 구분 없이** 전송 |
| **메시지 큐** | **메시지 단위**의 송수신 큐 — 경계가 구분됨 |

### 메시지 큐의 특징
- **"메시지 단위"**로 송수신
- **특정 프로세스를 대상**으로 메시지 전송 가능
- 메시지에 **우선순위(priority)** 부여 가능

---

## 2. 메시지 큐를 이용한 통신

임의의 프로세스는 메시지 큐에 대해:
- **put** : 메시지 큐에 메시지를 **쓰기**
- **get** : 메시지 큐로부터 메시지를 **읽기**

---

## 3. 여러 개의 큐 + 타입(type)

실제로 메시지 큐는 **여러 개의 큐를 동시에 제공**한다.

- 각 큐는 **타입(type) 값**으로 구분
- 메시지 송수신 시 프로세스는 **타입을 반드시 지정**해야 함

<img width="592" height="454" alt="image" src="https://github.com/user-attachments/assets/d2f8ae8e-910b-45e7-a164-80be4af8816f" />


```
타입
 1  →  msg4 │ msg3 │ msg2 │ msg1
 2  →  msg1
 3  →  msg2 │ msg1
 .
 .
 N
                          메시지 큐
```

### 타입 값 활용

| 타입 값으로 지정하는 것 | 효과 |
|----------------------|------|
| **프로세스 PID** | 특정 프로세스에게만 메시지 전송 가능 |
| **우선순위(priority)** | 우선순위 기반 메시지 전송 가능 |

---

## 핵심 요약

1. 파이프/FIFO = **스트림**(경계 X) / 메시지 큐 = **메시지 단위**(경계 O)
2. 동작: `put`(쓰기), `get`(읽기)
3. 메시지 큐는 **여러 큐를 동시 제공**, 각 큐는 **타입 값**으로 구분
4. 송수신 시 **타입 지정 필수**
5. 타입 = PID → 특정 프로세스 지정 / 타입 = 우선순위 → 우선순위 전송
