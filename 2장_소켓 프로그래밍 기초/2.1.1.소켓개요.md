# 2.1.1 소켓 개요

## 📌 소켓의 위치 (OSI 계층 관점)

소켓은 응용 프로그램(Application Layer, 5~7계층)과 전송 계층(TCP/IP) 사이의 **인터페이스** 역할을 한다. 응용 프로그램은 소켓 인터페이스를 통해 TCP/IP 스택에 접근한다.

| 계층 | 구성 요소 |
|------|-----------|
| 5~7 | Application |
| — | **Socket Interface** |
| 4 | TCP/IP (Transport) |
| 3 | TCP/IP (Network) |
| 2 | Network Driver |
| 1 | 물리 매체 |

## 🔢 소켓 번호 (Socket Descriptor)

- 소켓 개설 시 리턴되는 **`int`형의 socket descriptor**
- 소켓을 통해 IP packet을 송수신할 때 사용
- **descriptor table**에 의해 관리됨
  - 소켓을 사용하는 응용 프로그램마다 **각자의 descriptor table**을 가짐
  - descriptor table은 **파일 혹은 소켓 정보 구조체를 가리키는 포인터들**로 구성된 테이블

### 미리 지정되어 있는 descriptor (magic number)

| Descriptor | 의미 |
|:---:|---|
| `0` | standard input |
| `1` | standard output |
| `2` | standard error |

### Descriptor Table 구조

descriptor table의 각 엔트리는 파일 또는 소켓 정보 구조체를 가리키는 **포인터**이며, 소켓 정보 구조체에는 다음과 같은 필드가 들어있다.

- `service : SOCK_STREAM`
- `local IP`

## 🌐 IP 주소와 포트 번호

### IP 주소
IP 데이터그램을 **목적지 호스트까지 전달**하는 데 사용한다.

### 포트 번호
- IP 데이터그램에 실린 데이터를 **최종적으로 전달할 프로세스를 구분**하기 위하여 사용
- TCP/IP를 사용하는 **상위 프로세스를 구분**하는 식별자
- TCP/UDP 포트번호는 **각각 독립적으로 운영**되며 **1 ~ 65535** 사이의 값을 가진다
- 널리 사용되는 서비스를 위해 미리 정하여진 포트번호를 **well-known 포트**라 함

## 🔄 전체 그림: 소켓 · 포트 · IP의 관계

아래 그림은 응용 프로그램 → 소켓 → 포트 → TCP/UDP → IP로 이어지는 전체 구조를 보여준다.

<img width="942" height="587" alt="socket_port_overview" src="https://github.com/user-attachments/assets/2570a9d3-da4b-409c-ab3d-048e67b487c1" />


### 그림 해설

- **Application program 계층**: 각 응용 프로그램은 socket descriptor(`sd`)를 가진다.
  - Application 1은 `fd=3`(File Descriptor)과 `sd=4`(Socket Descriptor)를 모두 가짐
  - Application 2, 3, 4는 각각 `sd=3`을 가짐 (응용 프로그램마다 독립적인 descriptor table)
- **Socket 계층**: 응용 프로그램과 전송 계층을 잇는 접속점
- **Port number**: 3000, 3001은 TCP에 연결, 3002, 3003은 UDP에 연결
- **Transport layer**:
  - **TCP** → Connection-Oriented Service (Application 1, 2)
  - **UDP** → Connectionless Service (Application 3, 4)
- **Internet layer**: IP 주소(예: `210.94.213.194`)로 호스트 식별

### 약어 정리

| 약어 | 의미 |
|------|------|
| `fd` | File Descriptor |
| `sd` | Socket Descriptor |
| `IP` | Internet Protocol |
| `TCP` | Transport Control Protocol |
| `UDP` | User Datagram Protocol |

## ✅ 핵심 요약

1. **socket descriptor**는 `int`형 정수로, 응용 프로그램마다 별도의 descriptor table에서 관리된다.
2. descriptor `0`, `1`, `2`는 각각 stdin, stdout, stderr로 예약되어 있다.
3. **IP 주소**는 호스트를 식별하고, **포트 번호**는 호스트 내의 프로세스를 식별한다.
4. **TCP 포트와 UDP 포트는 서로 독립적**이며, 1~65535 범위의 값을 갖는다.
5. 자주 쓰이는 서비스에는 **well-known 포트**가 미리 할당되어 있다.
