# 5.2 소켓 옵션 종류

## SO_KEEPALIVE

- TCP 연결이 정상적으로 지속되고 있는지를 **주기적으로 확인**해주는 기능
- 옵션이 세트되어 있으면, TCP는 확인 시간(예: 2시간) 동안 데이터 송수신이 없을 때
  연결이 아직 살아있는지를 물어보는 질문(**keep-alive probe**)을 전송
- 디폴트: **동작 안 함**

### 세 종류의 응답

| 응답 | 의미 / 처리 |
| --- | --- |
| 상대방이 **ACK** 전송 | TCP 연결이 정상 동작 중 → 확인 시간 이후에 질문을 다시 전송 |
| 상대방이 **RST** 에러 전송 | 상대방 호스트가 꺼진 후 **재부팅된 상태** → TCP는 소켓을 닫으며 에러 코드는 `ECONNRESET` |
| **아무 응답이 없음** | 질문을 몇 번 더 보내본 후 연결 종료 (버클리 유닉스: 75초 간격으로 8개의 질문을 보낸 후 종료) |

- 비정상적인 TCP 연결 종료를 찾아내어 소켓을 종료하기 위해 사용

### 동작시키는 방법

```c
int set = 1;
setsockopt(s, SOL_SOCKET, SO_KEEPALIVE, (char *)&set, sizeof(set));
```

## SO_LINGER

- TCP 연결 종료를 위해 `close()` 호출
  - 기본 동작: TCP가 데이터를 모두 상대방에게 전송한 후 연결 종료하지만 **데이터 전송 보장은 안 됨**
- 상대방에서도 정상적으로 종료 절차가 이루어졌는지 확인하기 위한 옵션
- `close()` 는 지정한 **linger 시간 동안** 또는 정상적으로 종료가 이루어질 때까지 **블록**
- 정상 종료 전에 linger 시간이 타임아웃되면 `ETIMEDOUT` 에러 발생

### 지정 예

```c
struct linger {
    int l_onoff;   /* 0: 옵션 미사용, 1: 옵션 사용 */
    int l_linger;  /* 시간 설정 */
};

struct linger ling;
ling.l_onoff  = 1;
ling.l_linger = 0;   /* 송신 버퍼에 있는 데이터를 폐기하고 RST를 전송하여 TCP 연결을 즉시 리셋 */

if (setsockopt(sockd, SOL_SOCKET, SO_LINGER, (void *)&ling, sizeof(struct linger)) != 0) {
    perror("setsockopt fail");
    exit(1);
}
```

### `shutdown()`

- `close()` 호출 시 FIN이 전송되고, FIN에 대한 ACK가 수신되면 `close()` 는 즉시 리턴
  → 상대방이 전송할 데이터가 있는 경우 **데이터 손실 가능**
- 상대방이 FIN을 보낼 때까지 기다리기 위해 사용하는 함수

```c
int shutdown(int s, int how);
```

| 인자 | 설명 |
| --- | --- |
| `s` | 소켓 번호 |
| `how` | 양방향 스트림에 대한 동작 지정 |

| `how` 값 | 동작 |
| --- | --- |
| `SHUT_WR` | 송신 스트림만 닫는다 |
| `SHUT_RD` | 수신 스트림만 닫는다 |
| `SHUT_RDWR` | 송수신 양방향 스트림을 모두 닫는다 |

```c
write(sock, buf, size);             /* 상대방에게 데이터 전송 */
shutdown(sock, SHUT_WR);            /* 송신용 스트림 닫기, FIN이 전송됨 */
while (read(sock, buf, size) > 0);  /* read가 0을 리턴하면 상대가 FIN을 전송한 것 */
shutdown(sock, SHUT_RD);            /* 상대가 보낸 FIN에 대한 ACK를 전송하고 수신용 스트림 닫기 */
```

## SO_RCVBUF / SO_SNDBUF

- 소켓의 **수신 버퍼와 송신 버퍼의 크기를 변경**하기 위한 옵션
- 변경 시점
  - **클라이언트** : `connect()` 호출 **이전**
  - **서버** : `listen()` 호출 **이전**
- **3-way handshake 시에 버퍼 크기를 결정**하며, 이후에는 변경할 수 없음

## SO_REUSEADDR

- 소켓 주소 재사용 옵션. 동일한 소켓주소(**IP 주소 + 포트번호** 조합)를
  여러 프로세스에서 또는 한 프로세스의 여러 소켓에서 **중복 사용하는 것을 허용**

```c
int set = 1;
setsockopt(udp_sock1, SOL_SOCKET, SO_REUSEADDR, (void *)&set, sizeof(set));
```

### 옵션이 필요한 경우

#### 1) TIME-WAIT 상태에서의 주소 재사용

- 에코 서버나 채팅 서버를 `CTRL-C` 로 강제 종료 후 즉시 다시 실행하면
  **"Address in use" 에러**가 발생하여 서버를 실행할 수 없음
- TCP에서 active close를 하면 **TIME-WAIT 상태에서 2MSL 시간**을 기다리며,
  이 시간 동안에는 사용 중이던 포트번호를 중복 사용할 수 없음
- 옵션을 설정하면 TIME-WAIT 상태의 포트번호를 바로 재사용 가능 → **`bind()` 호출 전에** 지정

#### 2) 자식 프로세스가 서버인 경우

- 자식 프로세스가 서비스 처리 중에 부모 프로세스가 종료되었다가 다시 시작하면
  **"포트번호가 사용 중" 에러** 발생
- `bind()` 호출 전에 지정해야 함

#### 3) 멀티홈 서버의 경우

- 멀티홈 호스트에서 두 개 이상의 IP 주소가 같은 포트번호를 사용하는 것이 필요
- 예: 포트 80 http 서버를 멀티홈 서버에서 **IP 주소별로 여러 개 동시 실행** (별도의 소켓주소로 `bind()`)
- 하나의 프로세스 내에서 여러 소켓이 **같은 포트번호 + 서로 다른 IP 주소**를 사용하는 경우에 필요

#### 4) 완전 중복 바인딩

- 여러 프로세스(또는 한 프로세스 내 여러 소켓)에서 **동일한 IP 주소 + 동일한 포트번호**를 중복하여 `bind()`
- **UDP 소켓에서만** 사용 가능
- 멀티캐스트 데이터그램을 수신하는 경우 사용
  - 하나의 호스트 내 여러 멀티캐스트 가입자가 동일한 데이터그램을 수신하려고 할 때 사용

## 기타 옵션

| 옵션 | 설명 |
| --- | --- |
| `SO_OOBINLINE` | 상대방이 보낸 대역외(OOB: out of band) 데이터를 **일반 데이터 수신 버퍼에 같이 저장**하여 동등한 순서로 처리되도록 함 |
| `SO_RCVLOWAT` / `SO_SNDLOWAT` | 송·수신 버퍼의 **최소량(low-watermark)** 설정. 수신 최소량 기본 **1바이트**, 송신 최소량 디폴트 **2048바이트** |
| `SO_DONTROUTE` | 시스템이 배정하는 **라우팅 경로를 사용하지 않도록** 하는 옵션 |
| `SO_BROADCAST` | 소켓으로 브로드캐스트 메시지를 전송할 수 있도록 지정. **UDP 소켓에서만** 사용 가능하며, 이더넷과 같은 **방송형 서브네트워크**에서만 가능 |
| `TCP_NODELAY` | **Nagle 알고리즘**이 실행되지 않도록 하는 옵션 |
| `TCP_MAXSEG` | TCP의 최대 세그먼트 크기(**MSS**) 값을 읽거나 변경할 때 사용 |
