# 9.1.4 스레드의 동기화 문제

## 스레드의 동기화 문제란

- 한 스레드가 **공유 데이터를 액세스하는 도중**에 다른 스레드가 같은 공유 데이터를 액세스하면 **동기화 문제**가 발생
- 해결: **한 번에 한 스레드만** 공유 데이터에 접근하도록 해야 함
  - 이를 위해 **뮤텍스(mutex)** 사용
  - mutex = **mut**ual + **ex**clusion (상호 배제)의 합성어

---

## 동기화 문제의 예 (race.c)

멀티스레드 환경에서 발생할 수 있는 동기화 문제의 예제.

### 동작 개요

- 두 개의 스레드가 생성되며, 각 스레드는 `prn_data()` 함수를 연속적으로 호출
- 스레드 ID를 인자로 넘겨주고, `prn_data()` 함수 내에서 **스레드 ID와 인자로 넘겨준 값이 같은지**(그 사이에 변경되었는지)를 비교

### 문제의 원인

- 스레드들이 스레드 ID를 임시 저장하는 변수 `who_run`을 **공유**함
- 한 스레드가 `prn_data()`를 호출하는 동안 다른 스레드가 `prn_data()`를 호출하면 **`who_run`의 값이 변경**될 수 있음

```c
// 스레드 시작 함수
while (1) {
    prn_data(pthread_self());
}

void prn_data(long me) {
    who_run = me;
    if (who_run != pthread_self()) {
        printf("Error : %ld 스레드 실행중 who_run = %ld\n", me, who_run);
    }
}
```

---

## 플래그로 해결을 시도하면? (실패하는 접근)

플래그를 하나 정의하고, 이 값을 사용하여 한 스레드만 `prn_data()`를 실행하도록 하면 어떨까?

```c
void *thrfunc(void *arg) {
    while (1) {
        // 다른 스레드가 수행하지 않을 때만 수행
        if (who_run == -1) {
            prn_data(pthread_self());
        }
    }
    return NULL;
}
```

### 여전히 문제 발생

- **플래그를 조사한 직후**에 스레드 스케줄링이 일어나면 여전히 동기화 문제가 발생할 수 있음
- 즉, "플래그 검사 → 진입" 사이가 원자적(atomic)이지 않으므로 단순 플래그만으로는 해결되지 않음 → **뮤텍스 같은 동기화 도구가 필요**
