# 4.1 다중 처리 기술

## 다중 처리란?

동시에 여러 작업을 처리하는 것. 크게 두 가지 방식으로 나뉜다.

| 방식 | 설명 |
| --- | --- |
| **멀티태스킹(multitasking)** | 여러 작업을 **여러 프로세스(또는 스레드)** 들이 나누어 다중 처리 |
| **다중화(multiplexing)** | **한 프로세스 내**에서 여러 작업(다중 입출력 등)을 처리하는 다중 처리 기능 |

---

## 4.1.1 멀티태스킹

- 여러 작업(task)을 **병행하여 처리**하는 기법
- 유닉스에서는 프로세스를 여러 개 실행시키거나(**멀티프로세스**), 스레드를 여러 개 실행시키는 방법(**멀티스레드**)을 사용

### 멀티프로세스

독립적으로 처리해야 할 작업 수만큼 **프로세스를 만드는** 방법.

| 구분 | 내용 |
| --- | --- |
| **장점** | 각 프로세스가 독립적으로 작업을 처리하므로 **구현이 간편** |
| **단점** | ① 작업 수만큼 프로세스를 생성해야 함 → 프로세스가 많아질수록 **메모리 사용량 증가**, 스케줄링 횟수 증가로 **성능 저하**, 동시 개설 가능한 프로세스 수 제한<br>② **데이터 공유가 불편** → IPC(Inter-Process Communication)가 필요하여 구현이 복잡 |

### 멀티스레드

- **스레드** = 프로세스 내에서 독립적으로 실행되는 작업 단위
- 스레드를 생성하면 새 스레드는 원래 프로세스의 **이미지를 공유**
  (단, 스레드용 **스택 영역**은 스레드별로 별도 배정)

| 구분 | 내용 |
| --- | --- |
| **장점** | 한 프로세스 내 스레드들이 이미지를 공유 → **전역 변수**를 같이 사용하므로 데이터 공유가 쉬움 |
| **단점** | 여러 스레드가 한 데이터에 동시에 접근할 때 **동기화 문제** 발생 가능 |

---

## 4.1.2 다중화

### `read()` 의 동작 차이

| 대상 | 동작 |
| --- | --- |
| **파일** | 대부분 즉시 데이터를 읽거나, 잠시 기다리면 결과를 얻음 |
| **네트워크** | 수신 버퍼에 데이터가 있으면 바로 리턴, **없으면 도착할 때까지 계속 기다림(블록)** |

### 다중화의 필요성

- 한 프로세스에서 다수의 입출력을 처리할 때 **블록될 수 있는 입출력 함수를 사용하면 안 됨**
  - 한 곳에서 입출력이 블록되면 **프로그램 전체가 블록**됨
- 입출력 수만큼 프로세스(또는 스레드)를 생성하는 방법은, 생성 가능한 수에 **한계**가 있어 제한적
- **다중화** = 한 프로세스(또는 스레드) 내에서 이루어지는 다중 처리 기법

### 다중화 기법 3가지

| 기법 | 설명 |
| --- | --- |
| **폴링(polling)** | 처리해야 할 작업들을 **순차적으로 돌아가면서** 처리. 입출력이 블록되지 않도록 파일·소켓을 **non-block 모드**로 설정해야 함 |
| **셀렉트(selecting)** | 어떤 클라이언트로부터 데이터가 도착하면, 서버가 **데이터가 도착한 클라이언트의 입출력만** 처리. 유닉스에서는 `select()` 함수로 파일·소켓을 **비동기 모드**로 바꿔 처리 |
| **인터럽트(interrupt)** | 작업 처리 도중 특정 이벤트가 발생하면 해당 이벤트를 처리. 유닉스에서는 **시그널(signal)** 을 사용하여 입출력을 인터럽트 방식으로 처리 (시그널 = 소프트웨어 인터럽트) |

---

## 4.1.3 다중처리 예 — 채팅 프로그램

### 채팅 클라이언트

- 채팅에 참가하는 절차 필요
- 채팅 메시지 입력, 그리고 다른 클라이언트가 보낸 메시지를 **(서버를 경유하여)** 수신하여 화면에 출력하는 기능 필요

### 채팅 서버

- 클라이언트의 채팅 참가 요청을 접수하여 **참가 리스트에 추가**
- 참가한 클라이언트들이 보내는 메시지를 수신하여 **모든 참가자에게 방송(broadcast)**
- 여러 작업을 **병행 처리**하는 기능이 필요

### 서버 프로그램 유형

| 유형 | 처리 방식 |
| --- | --- |
| **멀티프로세스형** | 새 클라이언트가 접속될 때마다 프로세스를 만들고, 각 프로세스가 각 클라이언트와의 통신 담당 |
| **폴링형** | 소켓을 넌블록 모드로 설정하고, 돌아가면서 클라이언트의 입출력 상태 확인 |
| **셀렉팅형** | 셀렉팅을 이용하여 서버가 다수의 클라이언트와의 통신을 처리 |
| **인터럽트형** | 시그널을 이용하여, 연결 요청이 오거나 데이터가 도착하면 인터럽트 방식으로 처리 |
