# 6장 데몬 서버 구축 방법

- 서버 프로그램을 **데몬(daemon) 프로세스**로 실행시키는 방법을 소개
- 인터넷 서비스를 관리하는 **슈퍼 데몬 `inetd`** 를 이용하여, 사용자가 개발한 임의의 서버 프로그램을 호스트가 제공하는 네트워크 서비스 프로그램으로 등록

---

## 6.1 데몬 프로세스

### 데몬(daemon)이란?

- **백그라운드로 실행**되는 프로세스로서, **특정 터미널의 제어와 관계없이** 실행되는 프로그램
- 터미널에서 실행시킨 후 사용자가 **로그아웃하거나 `CTRL-C` 를 눌러도 종료되지 않음**
- 종료하려면 데몬에게 `kill` 또는 `SIGKILL` 시그널을 보내야 함

---

## 데몬 서버의 종류

### 1) 독립형(standalone) 데몬

- `httpd`, `sendmail`, `named` 등과 같이 **항상 실행되고 있으면서** 서비스를 제공하는 데몬
- 특정 서비스를 위한 **전용 프로그램**
- 특징
  - 질의에 대해 **더 빠르게 응답** 가능
  - 데몬 프로세스가 **항상 실행되고 있어야** 함
- 클라이언트의 요청 빈도가 많거나, 지속적으로 서비스를 제공해야 하는 경우에 주로 사용

### 2) `inetd` 데몬 (슈퍼 데몬)

- **슈퍼 데몬** 또는 **슈퍼서버(superserver)** 라고 함
- 여러 가지 인터넷 서비스 요청을 받아서 처리해 주는 **종합 인터넷 서비스용 데몬**
- 처리 방식
  - `echo`, `daytime` 과 같은 **간단한** 서비스 요청은 `inetd` 에서 **직접 처리**
  - `telnet`, `ftp` 와 같은 서비스 요청은 **새로운 프로세스를 생성**하여 처리
  - `telnet` 처럼 요청이 가끔 들어오는 서비스의 경우 **필요 시에만 실행**

| 구분 | 독립형(standalone) | 슈퍼 데몬(`inetd`) |
| --- | --- | --- |
| 실행 형태 | 항상 실행 | 필요 시 실행 |
| 응답 속도 | 빠름 | 상대적으로 느림 |
| 자원 사용 | 항상 점유 | 요청 시에만 사용 |
| 적합한 경우 | 요청이 잦고 지속적인 서비스 | 요청이 가끔 들어오는 서비스 |
| 예시 | `httpd`, `sendmail`, `named` | `telnet`, `ftp`, `echo`, `daytime` |

## 데몬 프로세스 생성

```c
// 프로그램을 데몬 프로세스로 실행시키는 코드
struct sigaction sact;
sigset_t mask;

if ((pid = fork()) != 0)
    exit(0);                          // 부모 프로세스 종료

setsid();                             // 새로운 세션/프로세스 그룹의 리더가 됨

// SIGHUP 시그널(hang up)을 무시한다
sact.sa_handler = SIG_IGN;
sact.sa_flags = 0;
sigemptyset(&sact.sa_mask);
sigaddset(&sact.sa_mask, SIGHUP);
sigaction(SIGHUP, &sact, NULL);

if ((pid = fork()) != 0)
    exit(0);                          // 다시 fork 후 부모 종료

chdir("/");                           // 작업 디렉터리를 루트로 변경
umask(0);                             // 파일 생성 권한 마스크 초기화

for (i = 0; i < MAXFD; i++)
    close(i);                         // 부모가 개설했을 모든 파일 디스크립터 닫기
```

### 각 단계 설명

| 코드 | 목적 |
| --- | --- |
| `fork()` 후 부모 `exit(0)` | 부모를 종료시켜 자식이 백그라운드에서 실행되도록 함 |
| `setsid()` | 자신을 **새로운 프로세스 그룹의 리더**로 만듦. 자신을 생성한 부모의 터미널·PID와의 관계를 끊기 위함 |
| `SIGHUP` 무시 | **터미널과 연결이 끊어졌을 때** 전송되는 시그널을 무시 |
| 두 번째 `fork()` | 세션 리더 지위를 버려, 다시 제어 터미널을 획득하지 못하게 함 |
| `chdir("/")` | 작업 디렉터리를 루트로 옮겨, 특정 디렉터리에 묶이지 않도록 함 |
| `umask(0)` | 새로 생성되는 파일이 임의의 소유 권한을 가질 수 있도록 함 |
| `close(i)` 반복 | 혹시 부모 프로세스가 개설했을지 모를 소켓·파일 디스크립터를 모두 닫기 위함 |
