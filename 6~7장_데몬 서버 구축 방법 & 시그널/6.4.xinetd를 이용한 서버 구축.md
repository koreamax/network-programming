# 6.4 xinetd를 이용한 서버 구축

- 리눅스에서는 `inetd` 와 TCP Wrapper 기능을 **`xinetd` 데몬**이 함께 제공

---

## `/etc/xinetd.conf`

xinetd가 지원하는 인터넷 서비스와 해당 포트를 정의하는 설정 파일.

| 구분 | 설명 |
| --- | --- |
| **defaults** 부분 | xinetd가 관리하는 **모든 서비스에 공통 적용**되는 설정 |
| **service** 부분 | **특정 데몬 서버**를 위한 설정 정의 |

---

## defaults 부분 설정

```
defaults
{
    instances       = 60
    log_type        = SYSLOG authpriv
    log_on_success  = HOST PID
    only_from       =
    per_source      = 5
    enabled         = pop3s imaps
}
```

| 속성 | 설명 |
| --- | --- |
| `instances` | 하나의 서비스에 대해 동시에 처리할 수 있는 **최대 요청 수** |
| `log_type` | 프로그램에 의해 생성되는 **로그의 형태**를 어떤 식으로 나타낼 것인지 정의 |
| `log_on_success` | 서버가 서비스를 **시작할 때** 어떤 정보가 로그에 남을 것인지 정의 |
| `log_on_failure` | 자원 부족으로 서버가 시작하지 못하거나, 규칙에 의해 접근이 차단되는 경우 어떤 정보가 로그에 남을 것인지 정의 |
| `per_source` | 특정 서비스별로 접속할 수 있는 **최대 접속자 수** |
| `enabled` | xinetd에서 지원하는 서비스 이름 설정. **이 속성에 설정된 서비스만 사용 가능**, 나머지는 불가 |
| `only_from` | 서비스를 이용하도록 **허용하는 원격 호스트** 정의. 기본적으로 모든 접근을 차단하며, service 부분에서 특정 서비스 접근을 허용 |

---

## service 부분 설정

특정 서비스에 대한 접근 설정에 사용한다.

```
service echo
{
    disable      = no
    socket_type  = stream
    wait         = no
    user         = root
    type         = INTERNAL
    id           = echo-stream
    protocol     = tcp
    only_from    = 210.115.36.0/24 192.168.1.0/24
    no_access    = 207.23.32.44
}
```

## xinetd를 이용한 에코 서버 (`tcpechoserv.c`)

### 동작 특징

- **소켓 관련 함수 호출이 없음**
- 지정된 포트 번호로 서비스 요청이 들어오면 **xinetd가 `accept()` 를 대신 호출**하여 클라이언트와 연결하고 서버 프로그램(echoserv) 실행
- xinetd가 클라이언트와 연결된 후, 소켓의 입출력을 서버 응용 프로그램의 **표준 입력(`stdin`) / 표준 출력(`stdout`)** 과 내부적으로 연결

### 서비스 등록 절차

#### 1) `/etc/services` 에 서버 등록

```
tcpechoserv    9200/tcp
```

#### 2) `/etc/xinetd.d/tcpechoserv` 파일 생성 (환경 설정)

```
service tcpechoserv
{
    disable         = no
    socket_type     = stream
    wait            = no
    user            = root
    server          = ~/tcpechoserv
    log_on_failure  += USERID
    port            = 9200
}
```

#### 3) xinetd 재시작

```bash
sudo /etc/init.d/xinetd restart
```

## xinetd 서비스 특징 (정리)

- TCP 연결 요청에 대해 `socket()`, `listen()`, `accept()` 함수가 **자동으로 처리**되며,
  내부적으로 `fork()` 와 `exec()` 가 실행되어 사용자가 등록한 서버 프로그램을 실행
- **항상 실행되는 것이 아니라 필요할 때만 실행**되며, 서비스가 종료되면 해당 서버 데몬 프로세스도 종료
- **클라이언트 요청 시마다 데몬이 실행**
  - 여러 클라이언트가 동시에 연결 요청하면 **클라이언트 수만큼 서버 프로세스가 실행** → 반응 속도가 느릴 수 있음
- **자주 실행되지 않는 서비스**에 적합
- 인터넷 서비스들에 대해 **규칙을 일괄적으로 적용**할 수 있어, 보안 정책 등을 일괄 설정하는 데 편리
