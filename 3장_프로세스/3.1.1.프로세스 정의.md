# 3.1.1 프로세스 정의

## 📌 개요

네트워크 프로그램에서 **여러 작업을 동시에 처리**하기 위해 멀티태스킹(multitasking) 프로그램을 사용한다.

### 멀티태스킹의 두 가지 방법

| 방법 | 설명 |
|------|------|
| **멀티프로세스** | 여러 프로세스를 통해 동시 처리 |
| **멀티스레드** | 한 프로세스 내의 여러 스레드를 통해 동시 처리 |

> 🎯 멀티프로세스를 이해하기 위해 **토크(talk) 프로그램**을 작성한다.

---

## 🔹 프로그램과 프로세스

| 용어 | 정의 |
|------|------|
| **프로그램(program)** | 프로그램 언어로 작성된 소스코드 |
| **프로세스(process)** | 실행중인 프로그램 |

> 💡 **소스코드 자체는 프로그램**이고, 그것이 메모리에 올라가 **CPU에서 실행되는 순간 프로세스**가 된다.

---

## 🔐 프로세스 모드

프로세스는 두 가지 모드에서 동작할 수 있다.

| 모드 | 권한 | 설명 |
|------|------|------|
| **사용자 모드 (User mode)** | 사용자의 권한 | 사용자의 권한으로 명령 실행 |
| **커널 모드 (Kernel mode)** | 커널의 권한 | 커널(운영체제의 핵심적인 부분)의 권한으로 명령 실행 |

### 예제 코드

```c
int main() {
    char buf[512];
    int n = read(0, buf, 512);   /* read() → 시스템 콜 → 커널 모드 진입 */
    n++;                          /* 사용자 모드에서 실행 */
    exit(0);
}
```

> 💡 일반적인 연산(`n++`)은 **사용자 모드**에서 실행되지만, `read()` 같은 시스템 콜이 호출되면 **커널 모드로 전환**되어 커널의 권한으로 입출력을 수행한다.

---

## 🔄 프로세스 상태

프로세스는 생성된 이후 종료될 때까지 **특정한 상태 중 하나**에 존재한다.

| 상태 | 영문 | 설명 |
|------|------|------|
| **실행** | running | 프로세스가 **CPU 서비스를 받을 수 있는 상태** |
| **블록** | waiting | **입출력 처리**나 어떤 **조건을 기다리는 상태** |
| **중단** | stopped | 프로세스 실행이 **잠시 중단된 상태** |
| **좀비** | zombie | 프로세스 실행은 끝났으나 **아직 종료 상태를 부모 프로세스에게 보내지 못한 상태** |

### 상태별 특징

#### 🟢 실행(running) 상태
- CPU를 점유하여 명령어를 실행 중
- 시간 할당량이 끝나거나 입출력 요청 시 다른 상태로 전이

#### 🟡 블록(waiting) 상태
- 입출력이 끝나거나 조건이 만족될 때까지 대기
- CPU를 사용하지 않음

#### 🟠 중단(stopped) 상태
- 외부 신호 등에 의해 일시 정지된 상태
- 다시 재개 가능

#### 🔴 좀비(zombie) 상태
- 프로세스는 종료되었지만 부모 프로세스가 **종료 상태(exit status)를 회수하지 않은 상태**
- 부모 프로세스가 `wait()` 등을 호출해야 좀비가 정리됨

> ⚠️ 좀비 프로세스가 쌓이면 시스템 자원(PID 등)을 낭비하므로 부모 프로세스는 자식의 종료를 적절히 처리해야 한다.

## ✅ 핵심 요약

1. 멀티태스킹은 **멀티프로세스** 또는 **멀티스레드** 방법으로 구현한다.
2. **프로그램**은 소스코드이고, **프로세스**는 실행중인 프로그램이다.
3. 프로세스는 **사용자 모드**(일반 명령)와 **커널 모드**(시스템 콜) 두 가지로 동작한다.
4. 프로세스 상태는 **running / waiting / stopped / zombie** 4가지가 있다.
5. **좀비**는 종료되었지만 부모가 종료 상태를 회수하지 않은 프로세스로, 부모의 처리가 필요하다.
