# 3.2 토크 프로그램

## 📌 개요

**TCP 소켓을 이용한 client-server program** 작성 예제로, 두 사람이 키보드로 메시지를 주고받는 토크(talk) 프로그램을 만든다.

### Non-block talk 방식

- **`fork()`를 사용하여 parent와 child가 메시지 송수신을 나누어 처리**
- 송신과 수신을 별도의 프로세스가 담당하므로 한쪽이 입력을 기다리는 동안에도 다른 쪽이 메시지를 받을 수 있음

### 입출력 사양

| 항목 | 내용 |
|------|------|
| **메시지 입력** | 키보드로부터의 **표준 입력** |
| **메시지 출력** | 모니터 화면으로 **표준 출력** |
| **프로그램 종료** | **특정 종료문자(escape character)** 입력 시 프로그램 종료 |

---

## 🏗 토크 프로그램의 구조

`fork()`로 프로세스를 둘로 나눈 뒤 역할을 분담한다.

| 프로세스 | 역할 |
|----------|------|
| **Parent process** | 키보드 입력 → 상대에게 **전송**(`write()`) |
| **Child process** | 상대로부터 **수신**(`read()`) → 화면 출력 |

> 💡 단일 프로세스라면 `read()`에서 블록되어 있는 동안 키보드 입력을 받지 못한다. `fork()`로 분리하여 **양방향 통신**을 동시에 가능하게 만든다.

---

## 🖥 토크 서버 프로그램

### 서버 주소 설정

```c
server_addr.sin_family = AF_INET;
server_addr.sin_addr.s_addr = htonl(INADDR_ANY);   /* server address setting */
server_addr.sin_port = htons(atoi(argv[1]));
```

| 필드 | 설정값 | 의미 |
|------|--------|------|
| `sin_family` | `AF_INET` | IPv4 주소 체계 |
| `sin_addr.s_addr` | `htonl(INADDR_ANY)` | **모든 로컬 IP 주소**에 바인딩 (wildcard) |
| `sin_port` | `htons(atoi(argv[1]))` | 명령행 인자로 받은 포트 번호 |

> 💡 `INADDR_ANY`를 사용하면 호스트가 가진 어떤 인터페이스로 들어오는 연결이라도 받을 수 있다.

### 송수신 분담 — `fork()` 후 분기

```c
if ((pid = fork()) > 0) {
    /* === parent process === */
    while (fgets(sendline, MAXLINE, stdin) != NULL) {     /* gets from standard input */
        write(client_fd, sendline, strlen(sendline));     /* send message to client */

        if (strstr(sendline, escapechar) != NULL)         /* check exit condition */
            close(s);
    }
}

if (pid == 0) {
    /* === child process === */
    read(client_fd, recvline, MAXLINE);                   /* receive message from client */

    if (strstr(recvline, escapechar) != NULL)             /* check exit condition */
        close(s);
}
```

### 서버 프로세스 역할

| 프로세스 | 함수 | 동작 |
|----------|------|------|
| **Parent (송신)** | `fgets()` | stdin에서 메시지 입력 받음 |
| | `write(client_fd, ...)` | 클라이언트로 메시지 전송 |
| | `strstr() + close()` | escape 문자 확인 후 종료 |
| **Child (수신)** | `read(client_fd, ...)` | 클라이언트로부터 메시지 수신 |
| | `strstr() + close()` | escape 문자 확인 후 종료 |

## 💻 토크 클라이언트 프로그램

### 송수신 분담 — `fork()` 후 분기

```c
if ((pid = fork()) > 0) {
    /* === parent process === */
    while (fgets(sendline, MAXLINE, stdin) != NULL) {     /* gets from standard input */
        write(s, sendline, strlen(sendline));             /* send message to server */

        if (strstr(sendline, escapechar) != NULL)         /* check exit condition */
            close(s);
    }
}

if (pid == 0) {
    /* === child process === */
    read(s, recvline, MAXLINE);                           /* receive message from server */

    if (strstr(recvline, escapechar) != NULL)             /* check exit condition */
        close(s);
}
```

### 클라이언트 프로세스 역할

| 프로세스 | 함수 | 동작 |
|----------|------|------|
| **Parent (송신)** | `fgets()` | stdin에서 메시지 입력 받음 |
| | `write(s, ...)` | 서버로 메시지 전송 |
| | `strstr() + close()` | escape 문자 확인 후 종료 |
| **Child (수신)** | `read(s, ...)` | 서버로부터 메시지 수신 |
| | `strstr() + close()` | escape 문자 확인 후 종료 |

---

## ⚖️ 서버 vs 클라이언트 코드 비교

서버와 클라이언트는 **거의 동일한 구조**이며, 차이는 사용하는 소켓 디스크립터뿐이다.

| 항목 | 서버 | 클라이언트 |
|------|:---:|:---:|
| 송수신용 소켓 | `client_fd` (`accept()`로 얻은 것) | `s` (`socket()`으로 얻은 것) |
| Parent | `write(client_fd, ...)` | `write(s, ...)` |
| Child | `read(client_fd, ...)` | `read(s, ...)` |

> 💡 서버는 `accept()`로 얻은 새 소켓(`client_fd`)으로 통신하고, 클라이언트는 `socket()`으로 얻은 소켓(`s`)을 그대로 사용한다.

## 🔑 핵심 메커니즘 정리

### 1. 왜 `fork()`로 나누는가?

단일 프로세스에서는 `read()`가 블록되면 `fgets()`로 입력을 받지 못한다. 두 작업을 **동시에** 하려면 프로세스를 둘로 나눠야 한다.

### 2. 종료 처리

```c
if (strstr(sendline, escapechar) != NULL)
    close(s);
```

송신 메시지에 **escape 문자가 포함되어 있으면** `close()`를 호출하여 소켓을 닫는다. `strstr()`은 첫 번째 인자에서 두 번째 인자가 등장하는 위치를 찾는 함수.

### 3. 양방향 흐름

```
Client (parent: 송신) ─── write ───→ Server (child: 수신) ─── read
Client (child: 수신) ←── read  ─── Server (parent: 송신) ─── write
```

부모는 **송신 전용**, 자식은 **수신 전용**으로 양쪽 끝에서 대칭적으로 동작한다.

---

## ✅ 핵심 요약

1. 토크 프로그램은 **TCP 소켓 + `fork()`** 조합으로 양방향 채팅을 구현한다.
2. **Parent는 송신**(`fgets` → `write`), **Child는 수신**(`read` → 출력)을 담당한다.
3. 서버는 `INADDR_ANY`로 모든 인터페이스에 바인딩하며, 포트는 명령행 인자로 받는다.
4. **escape 문자**가 메시지에 포함되면 `close()`로 소켓을 닫아 프로그램을 종료한다.
5. 서버와 클라이언트의 송수신 코드는 **사용하는 소켓 디스크립터만 다를 뿐 거의 동일한 구조**이다.
